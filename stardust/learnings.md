# Learnings — replica migration of balbriggan.ie/community-development/ (2026-09-23)

- **Root ≡ page needs a coverage row and a `/` path.** When the site root is delivered as the `/index` document, the served sitemap lists `/` while coverage knows only the page; `assemble.mjs --verify-origin` flags `/` as extra and `verify.mjs` 404s on the literal `/index`. One `update-coverage.mjs --new index --path /` row settles both.
- **gate.sh's built-in chrome probe reads the bare `header`/`footer` elements.** On a WordPress/Bootstrap theme those are the title band and an empty element, so the round exits 2 with spurious deltas while pixel, height, content and overflow pass; re-probe the real regions (`nav.navbar`, `#wrapper-footer-full`) with `chrome-parity.mjs --region` and record that file beside the round.
- **Sticky wrapper vs sticky host is not a parity delta.** Live `div.sticky-top > nav.navbar{relative}` and build `header{sticky} > .navbar{relative}` are the same structure; a region probe that pairs the inner live element with the outer build element reports `relative → sticky`. Check the element pairing before filing a foundation request.
- **Cluster subagent with a complete brief delivered the unit in one round.** Frozen-file list, token-by-file rule, exact gate command with `--marker`, the recorded defects and the prior published numbers in the brief meant one pixel round per width (22.81 % → 2.47 %, 11.41 % → 4.40 %) and one report of ~15 lines.
- **`npm run lint:fix` reaches into `stardust/`.** The boilerplate lint touched `stardust/migrated/assets/js/motion.js` and `stardust/prototypes/js/motion.js`; revert those before committing or scope the lint run to `blocks/` and `styles/`.
