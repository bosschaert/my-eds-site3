## Fonts — decisions
- Self-hosted @font-face in canon.css, `font-display: swap`, same family names, per-weight faces (Inter 300/400/500/600; Playfair Display 400/500/600 normal + italic; Rasa 400/500/600), each in the three subsets the page can hit: gujarati (Rasa only), latin-ext, latin, with the unicode-range copied from google-fonts.css. Declaration order per weight = gujarati, latin-ext, latin (Google's order).
- URLs are `../assets/fonts/<file>` because the sheet lives in `/css/` (round 1 used `assets/fonts/...` → 404 → fallback fonts; fixed in round 2).
- Capture-state item 1: the manifest's `*-latin-ext.woff2` files are byte-wise the **vietnamese** subset (their gstatic URL maps to the vietnamese unicode-range in google-fonts.css) and `rasa-*-gujarati.woff2` / `playfair-display-600-gujarati.woff2` are byte-identical duplicates of the latin files (md5 a3990596… / ef05b30d…). So the real Gujarati Rasa glyphs for "આવજો." were NOT captured. Map: `lift/fonts-map.txt`.
- Capture-state item 2 (found by measurement, rounds 2→3): with the captured files self-hosted, every box matched live except text-wrap-sensitive ones (`#conversation h2` 3 vs 4 lines, `#story-bouquet-home .lede` 3 vs 2, `.btn` widths ±3 %) while all 29 typography computed properties were equal. A size sweep (`measure-typo-sweep.txt`) showed sign-flipping width deltas (−11 px @11px, +19 @19px, +14 @32px, −9 @40px) between a Google-loaded page and the self-hosted one — advance-rounding, not metrics. Cause: Google Fonts serves **different builds per UA**. The capture (curl, Chrome/129 UA) got hinted builds (`prep` table present; same fontRevision), whereas the harness's real Chrome (UA Chrome/143) gets unhinted builds at different URLs (`…1ZL7W0Q5nw.woff2` etc.). A local copy of the prototype loading the live Google `<link>` reproduced the live numbers exactly (`measure-gfonts-probe.txt`), and the captured google-fonts.css reproduced mine (`measure-typo-gfcss.txt`).
- Resolution: fetched the files Google serves to Chrome/143 for the three subsets the page can hit (9 files, 29 faces) into `stardust/current/assets/fonts/gf143/` (names `<family>-v<ver>-<style>-<subset>-<hash8>.woff2`; original URLs in `lift/fontface-gf143.css`) and generated canon.css's @font-face block from that CSS verbatim (same family/style/weight/display/unicode-range; `src` → `../assets/fonts/gf143/…`). With these, round 3 is Δ0 on every section at both widths. The captured per-weight files and the five `*-vf-*.woff2` files fetched earlier (true latin-ext/gujarati subsets at the curl-UA URLs) remain in the folder, unused.
- Not loaded by the live page and therefore not used here: `→` (U+2192) is outside every declared range and falls back to the next family on live as well.

## Gate iter1 → fix (2026-10-12)
- 1440 iter1: 0.17 % pixels, height Δ −31 px (build 7630 vs live 7599); 360 iter1: 0.15 %, Δ 0. All bands ≤ 0.4 %; rows 7599–7630 of the build capture were unpainted canvas.
- Cause (measured with a load/scroll trace): the lazy-loaded "My Books" image carries `width="1536" height="1024"` on the live page while the file is 1672×941; until it loads the browser reserves 327 px instead of 296 px, so the pre-load document is 31 px taller. The live capture's settle pass loads it before the height read; the build capture reads the height first.
- Fix: the prototype declares the file's true intrinsic size (`width="1672" height="941"`). Rendered geometry after load is unchanged on both sides; only the pre-load reservation differs from the live markup. Capture-state note for delivery: the EDS pipeline emits its own width/height from the uploaded asset, so this needs no special handling. host-mirror declares 1122×1402 for a 1200×1499 file — same ratio to 4 decimals, no layout effect, left as live.
- Motion compare (iter2) reported `transition width: MISSING on build` — 398 live events on `div.nm-reading-progress > span`: a 2 px fixed reading-progress bar (gold) at the top of the viewport whose width follows scroll, injected by site-enhancements.js (not in the authored HTML, hence missed). Added: markup as first child of body (live prepends it), CSS lifted from home.css @50992/@51110 (+ reduced-motion `transition: none` @57517), and a minimal rAF-ticked scroll handler with the live formula scrollY / (scrollHeight − innerHeight).
